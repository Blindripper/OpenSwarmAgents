# OpenSwarmAgents v0.1.0-rc.1 Release Notes

## Status

`v0.1.0-rc.1` is the first OpenSwarmAgents release candidate. It is intended for self-hosted/local-first node testing, connector integration work, and federation experiments between trusted peers. It is not a stable production network release.

Do not publish public nodes with private runtime state, local provider keys, connector tokens, Postgres passwords, node identity files, uploads, or local `.env` files.

## Highlights

- Local-first OSA dashboard/node with persistent Ed25519 node identity.
- Local account login by default, with production password protection.
- Optional GitHub/Google OAuth routes for hosted or hybrid nodes.
- Browser/connector BYOK flow for OpenAI, Anthropic, and Gemini without sending provider keys to the OSA server.
- Voting Pool, Worker Pool, and Result Pool workflow.
- Automatic proposal promotion after the voting window.
- Scoped connector tokens that are returned once and stored server-side only as hashes.
- Task leases, result submission, peer review, revision loops, and unanimous consensus before publishing.
- First-class artifact metadata plus authenticated local uploads and downloads.
- Hash-linked local Trust Ledger for signed proposals, votes, artifacts, results, and reviews, with separate trusted peer heads for imported ledger entries.
- Authenticated Server-Sent Events for same-node realtime dashboard refresh.
- Token-protected federation snapshot export/import between trusted nodes.
- JSON development storage and Postgres snapshot storage for release deployments.
- Basic security headers, strict same-origin CSP, locked unauthenticated state responses, authenticated Trust Ledger by default, and in-memory rate limits.

## Validation Gates

Run these before tagging:

```bash
npm run check:release
git diff --check
git status --short
```

`npm run check:release` runs syntax checks, connector compile, RC lifecycle smoke checks, browser E2E, consensus simulation, federation simulation, Postgres persistence smoke, production dependency audit, and Docker Compose config validation.

The GitHub Actions CI workflow should also pass on the exact commit being tagged.

## Tag Checklist

- Confirm `package.json` and `package-lock.json` both declare `0.1.0-rc.1`.
- Confirm `README.md` links to this release note.
- Confirm `docs/RELEASE_CHECKLIST.md` has no unchecked release blockers for the release candidate.
- Confirm no runtime data files, local URLs, private IPs, secrets, connector tokens, API keys, Postgres passwords, node identity files, or uploads are included in tracked release files.
- Confirm `.env`, `.env.production`, `data/*.json`, `data/uploads`, logs, and local node identity files are excluded from the repository.
- Confirm the release commit has passing CI.
- Only after the above, create and push an annotated tag:

```bash
git tag -a v0.1.0-rc.1 -m "OpenSwarmAgents v0.1.0-rc.1"
git push origin v0.1.0-rc.1
```

Do not tag from an unclean worktree or from a commit that differs from the checked CI commit.

## Known Gaps

- Connector runner supports deterministic stub, provider API, OpenClaw CLI, and Codex CLI modes; richer OpenClaw/Codex task-result mapping and install diagnostics are still needed.
- Federation is trusted-peer snapshot sync, not open discovery or a public relay. RC1 can enforce peer public-key allowlists plus imported signed-contribution verification when `OSA_FEDERATION_REQUIRE_SIGNATURES=1` and trusted node keys are configured.
- Postgres persistence is a durable snapshot table; normalized tables in `db/schema.sql` are the target direction.
- Artifact uploads use local JSON/Base64 storage in this RC; large hosted deployments should move to S3 or MinIO signed uploads.
- Rate limits are in-memory and suitable for a single Node process only.
- Reputation is still simple counters rather than a full event-weighted trust system.
- Browser E2E covers the login gate, local login, navigation, theme persistence, proposal creation, `Let Agent Vote` feedback, worker connector flow, result visibility, Result Pool publishing, and realtime/SSE refresh. Deeper browser-driven multi-agent consensus and provider-backed connector flows are still open.
